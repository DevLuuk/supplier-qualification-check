# Supplier check

The tool reads the documents a subcontractor sends for onboarding and checks them against fixed rules.
A language model only reads the documents and copies values with a quote; plain Python code decides pass, fail or unsure.
The officer sees each rule with its proof, gets a draft email for anything missing, and approves or rejects.

All firms, documents, register and sanctions data are mock, and the lookups say MOCK on screen.

Demo video, 8 minutes: https://drive.proton.me/urls/01QJCNNHT8#kLMQ8TTlkSlK

## From clone to demo

```bash
git clone https://github.com/DevLuuk/supplier-qualification-check.git && cd supplier-qualification-check
uv sync
cp .env.example .env   # then put your Gemini key after GOOGLE_API_KEY=
uv run python -m supplier_check.pipeline data/firms/weber-stahlbau
uv run streamlit run src/supplier_check/app.py
```

The command line run prints the verdicts and saves the full result to `eval/results/<firm>.json`.
Model answers are cached in `eval/cache/`, so a second run of the same firm makes no model calls.
Add `--thinking normal` to the command line run to let the reading model think longer; the default is minimal.
Run `uv run pytest -q` for the rule tests, which need no key.

```bash
uv run python eval/run_eval.py            # rebuilds docs/eval_report.md from the saved runs and the answer keys
uv run python scripts/make_mock_data.py   # regenerates the mock firms, deterministic
```

## Documents

- `docs/executive-summary.md` (also as PDF): the ask, the value, the risks and the rollout on one page. Stands alone.
- `docs/design.md` (also as PDF): the user and the flow, how it is built and what was bought, how a value earns trust, how I know it works, the path to production, the assumptions and the kill test.
- `docs/eval_report.md`: the measured numbers behind every claim, generated by the eval script.

All firms, documents, register and sanctions data are mock. Every number that is not from the case is labelled measured or assumed.
